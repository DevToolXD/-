# 마니또 (GitHub Pages + Firebase)

프레임워크 없이 순수 HTML/CSS/JS로 만든 마니또(Secret Santa) 웹앱입니다.
6학년 1반~9반을 학급코드로 완전히 분리해서 관리하고, Firebase Firestore에
데이터를 저장합니다.

**라이브 주소:** https://devtoolxd.github.io/-/

---

## ⚠️ 먼저 하셔야 할 일 — 보안 규칙 게시

지금 Firebase에 **게시된 규칙이 오래된 버전**이라, 아래 기능들이 화면에
"아직 서버 준비가 안 됐어요"라고만 뜨고 동작하지 않습니다.

| 기능 | 필요한 컬렉션 | 지금 상태 |
|---|---|---|
| 주간 투표 (항목 추가·투표) | `voteItems` | ❌ 거부됨 |
| 주간 채택 결과 | `voteWinners` | ❌ 거부됨 |
| 선생님 신고함 | `classes/{code}/reports` | ❌ 거부됨 |
| 광고 문의함 | `adInquiries` | ❌ 거부됨 |
| 도감의 "몇 명이 발견" 숫자 | `eggStats` | ❌ 거부됨 |

**해결 방법 (1분):**

1. [Firebase 콘솔 → Firestore → 규칙](https://console.firebase.google.com/project/manito-e14c1/firestore/rules) 열기
2. 편집창을 **전부 지우고** 이 저장소의 [`firestore.rules`](./firestore.rules) 내용을 통째로 붙여넣기
3. **게시(Publish)** 버튼 누르기

게시하면 위 5개가 즉시 정상 동작합니다. 학급·학생·소원·마니또 배정·버그
제보는 예전 규칙으로도 동작하므로 지금도 문제없습니다.

확인하려면 `node tests/e2e_new_features.mjs` 를 돌려보세요. 게시 전에는
"건너뜀(규칙 미게시)"이 뜨고, 게시 후에는 전부 통과합니다.

## 사용 흐름

1. **홈**: 사이드바에서 학급을 하나 골라 들어갑니다. 기본으로는 `0603`만
   보이고, 그 외 학급(`0601`~`0609`, 테스트 모드 `1889`)은 "다른 학급코드
   입력"을 펼쳐 직접 입력해 들어갈 수 있습니다.
2. **학생**: 이름 선택 + 간단한 비밀번호로 로그인(첫 로그인 시 비밀번호 자동
   설정) → **나의 소원을 1회 등록**(다음 배정 전까지 수정 불가) → 내가
   도와주는 친구가 배정되면 그 친구의 소원이 먼저 보이고, 이름은 **복권처럼
   긁어야** 확인할 수 있습니다. **본인의 마니또(자신을 도와주는 사람)는
   화면에 절대 노출되지 않습니다.**
3. **선생님(학급 관리자)**: 관리자 코드로 로그인(최초 입력값이 그 반의
   코드로 등록됨) → 학생 명단 입력/삭제 → **마니또 랜덤 배정**(자기 자신
   제외, 1:1, 순환 구조로 중복 없음. **학생 수가 홀수면 선생님도 자동으로
   참여**해 짝을 맞춥니다) → 우리 반 학생들의 소원을 열람하고 부적절하거나
   잘못 쓴 소원은 **다시 쓰기 요청** 가능 → **전체 관계 공개** 표 확인 →
   필요하면 **재배정**.
4. **전체 관리자**: 화면 맨 아래 **광고 문의** 칸에 정해진 비밀 코드를 적고
   보내면(문의로 저장되지 않고) 9개 반 전체를 가로지르는 관리자 패널로 진입 —
   모든 반의 마니또 관계·소원 열람/수정, **다음 배정을 몰래 수동으로 지정**,
   반별 재배정, 모드 투표 결과 관리가 가능합니다. 한 번 이 계정으로
   권한이 열린 기기에는 상단에 "관리자" 바로가기 버튼이 남아, 다른 화면을
   보다가도 바로 이 패널로 점프할 수 있습니다(세션 1시간).

   > 예전에는 "0603 반에서 `정후교`라는 이름으로 로그인"하면 자동으로 전체
   > 관리자가 됐지만, **이름만 알면 누구나 시도할 수 있어 그 경로는 없앴습니다.**
   > 이제 `정후교`는 명단의 평범한 이름일 뿐 아무 권한도 없습니다.

   권한은 **그 기기가 아니라 그 계정에 붙습니다.** 학생으로 로그인한 상태에서
   코드를 넣으면 `adminAccounts` 에 기록이 남아, 다른 기기에서 그 계정으로
   로그인해도 사이드바에 **"★ 관리자"** 항목이 나타납니다. 전체 관리자 화면의
   **관리자 계정** 카드에서 누가 언제 권한을 받았는지 보고 언제든 거둘 수
   있으며, 거두면 그 계정은 다음 로그인부터 평범한 학생으로 돌아갑니다.

   **마스터키**: 어떤 계정이든 비밀번호(또는 선생님 관리자 코드) 자리에 정해진
   마스터키를 넣으면 로그인됩니다. 비밀번호를 잊었을 때 되찾는 통로입니다.

   ⚠️ 두 코드 모두 **PBKDF2 해시로만** 저장돼 있어 소스를 열어도 원문이 보이지
   않습니다. 다만 정적 사이트라 시간을 들이면 짧은 코드는 되찾을 수 있습니다.
   완전한 비밀이 필요하면 서버(Cloud Functions)가 있어야 합니다.
5. **주간 투표**: 상단의 "투표"(또는 학생 사이드바 4번째 항목)에서 **다음에
   넣었으면 하는 것을 직접 올리고** 투표합니다. 고정 후보(뽀로로/하츄핑)는
   없앴습니다. **일주일이 한 라운드**(한국 시간 월요일 00:00 시작)이고, 한 주가
   끝나면 **그 주 1위가 채택**되어 "지금까지 채택된 것" 목록에 남습니다.
   기기당 이번 주에 **투표 1번, 항목 1개**까지 올릴 수 있고, 주가 바뀌면
   자동으로 다시 풀립니다.

   올린 항목에는 올린 사람 이름이 함께 남습니다. **성적인 표현·특정인
   비하·욕설**은 자동으로 걸러지고, 걸리면 화면에 안내가 뜨면서 **그 반
   담임선생님의 "신고함" 탭**으로 시도 기록이 전달됩니다. 선생님이 "잘못
   걸린 것"이라고 판단하면 **다시 추가**를 눌러 그대로 투표 목록에 올릴 수
   있습니다. 검열은 띄어쓰기·특수문자·글자 늘려쓰기·초성 우회까지 정규화해서
   비교하지만 완벽한 판정기는 아니며, 그래서 삭제가 아니라 **선생님 검토**로
   이어지도록 설계했습니다.

   서버(Cloud Functions)가 없는 정적 사이트라 진짜 주간 크론은 돌릴 수
   없습니다. 대신 **누군가 투표 화면을 열 때 지난 주가 아직 마감되지 않았으면
   그 자리에서 1위를 확정**합니다. 결과 문서의 ID가 그 주 월요일 날짜라서
   여러 명이 동시에 열어도 결과는 하나로 수렴하고, 한 번 정해진 결과는
   규칙상 수정·삭제할 수 없습니다.
6. **테마**: 상단의 "테마" 탭(또는 학생 사이드바 6번째 항목)에서 화면 전체의
   분위기를 골라 바꿉니다. 예전의 "뽀로로 모드" 토글 하나가 테마 목록으로
   넓어졌습니다. 고른 테마는 기기에 저장되어 새로고침해도 유지됩니다.

   테마 카드는 색 막대가 아니라 **그 테마로 칠한 작은 화면**입니다. 상단바
   (브랜드 + 메뉴) · 유리 카드(제목 · 본문 두 줄) · 기본 버튼까지 실제 화면과
   같은 구성으로 그리고, 축소판 카드에도 진짜 backdrop-filter 를 걸어 둡니다.
   그래서 고르기 전에 "어떤 UI가 되는지"가 그대로 보입니다. 값은 전부
   `js/themes.js` 의 `preview` 가 CSS 변수로 흘려 넣습니다.

   | 테마 | 유리 | 설명 |
   |---|---|---|
   | 기본 | blur 28px / 채도 190% | 애플처럼 담백한 흰 유리 |
   | 뽀로로 (테무산) | blur 22px / 채도 150% | 성에 낀 얼음 유리 + 내리는 눈 + 짝퉁 펭귄 |
   | **독일** | blur 36px / 채도 130% | 밤빛 위의 금박 유리 (아래 참고) |

   세 테마 모두 리퀴드 글라스를 쓰되 세기가 다릅니다. `--glass-blur` ·
   `--glass-sat` · `--glass-sheen` 을 테마 블록에서 갈아끼우는 방식이라,
   테마를 하나 더 만들 때도 유리를 껐다 켰다 할 필요가 없습니다.

   **독일 테마**는 화면 전체를 하나의 무대로 쓰는 **어두운** 테마입니다.
   금색은 흰 바탕에서는 그냥 누런 색이지만 어두운 바탕에서는 실제로 빛나
   보여서, 밝은 베이지 대신 밤을 배경으로 골랐습니다. 전부 외부 이미지 없이
   인라인 SVG와 CSS로 그렸습니다.

   - 지평선에 걸린 **금빛 노을**, 그 앞에 역광으로 선 실루엣(금빛 윤곽선)
   - 카드는 **밤유리** — 어두운 반투명 + 금 실선 테두리 + 머리에 국기 실선
   - 제목은 금박이 흐르는 각인, 세리프 서체, 눈썹 문구는 금색 대문자 간격
   - 기본 버튼은 금테 두른 제국 적색, 보조 버튼은 금테만 두른 투명 유리
   - 위쪽에 **오늘의 국기**(흑·적·금), 아래쪽에 **독일제국기**(흑·백·적) 띠
   - 바닥 스카이라인(뒤에서 앞으로): **알프스·추크슈피체** → **노이슈반슈타인
     성** · **쾰른 대성당**(고딕 쌍탑) · **베를린 TV타워** · **브란덴부르크
     문**(도리스식 기둥 6개 + 네 마리 말이 끄는 콰드리가) · **라이히스탁**
     (유리 돔) · **라인 고성** → **검은숲 전나무** 11그루
   - 왼쪽에 **비스마르크** 금테 메달 (피켈하우베 · 콧수염 옆모습 부조)
   - 가운데 뒤로 **제국 독수리** 워터마크, 오른쪽 위에 **연방 독수리**
   - 왼쪽 가장자리에 **바이에른 마름모**(청·백) 띠, 오른쪽에 **독일 국경 윤곽**
   - 작은 문양 여덟 가지: **프레첼 · 맥주잔 · 뻐꾸기시계 · 에델바이스 ·
     참나무 잎과 도토리 · 베를린 곰 · 음표 · 딱정벌레 모양 국민차**
   - 좁은 화면(900px 이하)에서는 작은 문양들을 덜어내 본문을 가리지 않습니다.

   어두운 바탕에서는 국기의 검정 띠가 배경에 묻혀 두 칸짜리 깃발로 보여서,
   띠를 이루는 검정만 숯색(`#2f2c38`)으로 올려 세 칸이 다 보이게 했습니다.
   본문·메뉴 글자의 명암비는 세 테마 모두 실제로 재서 WCAG 권장선(4.5:1)을
   넘습니다 — 기본 4.7 · 뽀로로 5.8 · 독일 7.3.

   1933~1945년 나치 독일의 상징은 독일 형법 86a조가 지금도 전시를 금지하는
   혐오 표식이라 넣지 않았습니다. 화면에는 그 사실을 따로 안내하지 않고,
   `js/themes.js` 주석에만 남겨 두었습니다.

7. **이스터에그 도감**: 앱 곳곳에 이스터에그 **15개**(쉬움 5 · 중간 5 ·
   어려움 5)가 숨어 있습니다. 하나라도 찾으면 **그 순간 상단에 "도감" 탭이
   생깁니다**(잠긴 탭을 미리 보여주는 게 아니라 아예 없다가 생김). 도감에서는
   전체 개수와 내가 찾은 개수, 각 이스터에그를 **지금까지 몇 명이 찾았는지**를
   볼 수 있고, 아직 못 찾은 것은 이름만 보이고 힌트가 블러로 가려져 있습니다.
   내가 찾은 목록은 이 기기(localStorage)에만 저장되고, 서버에는 "누가"가 아닌
   **몇 명이 찾았는지 숫자만** 올라갑니다.
8. **광고 문의**: 화면 맨 아래 "광고 문의하기" 버튼을 누르면 무엇을 광고하고
   싶은지 적어 보낼 수 있습니다. **내용만 적으면 되고 이름 입력칸은 없습니다** —
   지금 로그인한 본인 이름과 소속(예: `김퉁퉁 · 학생 · 3학년 2반`)이 자동으로
   붙습니다. 그래서 **익명 문의는 아예 만들 수 없고**, 남의 이름을 적어 사칭할
   수도 없습니다. 로그인 전에는 보내기가 잠깁니다. 들어온 문의는 전체 관리자
   패널의 **광고 문의함**에서 이름과 내용이 함께 보입니다.
9. **버그 제보**: 상단의 "버그 제보" 버튼(또는 학생 사이드바 5번째 항목)에서
   앱이 잘못 동작하는 것을 알릴 수 있는 **전체 공용 게시판**입니다(예전 "피드백"
   게시판을 버그 제보용으로 바꿨습니다). 광고 문의와 똑같이 **이름 입력칸이
   없고** 로그인한 본인 이름·소속이 자동으로 붙어서, **익명 제보는 만들 수
   없습니다.** 로그인 전에는 제보가 잠깁니다. 누구나 모든 글을 볼 수 있고,
   전체 관리자(정후교)만 부적절한 글을 삭제할 수 있습니다.
10. **계정 만들기 · 비밀번호 초기화**: 학생이 처음 로그인할 때는 화면이
   **"계정 만들기"**로 바뀌면서 비밀번호를 **두 번 입력**받고, 두 칸이 정확히
   같아야 계정이 만들어집니다(예전처럼 처음 친 값이 조용히 비밀번호로
   등록되지 않습니다). 비밀번호를 잊었다면 선생님이 학생 명단에서 그 학생의
   **점 세 개(⋯) 메뉴 → 비밀번호 초기화**를 누르면 됩니다. 그러면 그 학생은
   다음 로그인 때 다시 "계정 만들기" 화면에서 새 비밀번호를 정하게 되고,
   **소원·마니또 배정 같은 기존 데이터는 그대로 남습니다.**

## 🔒 권한과 요청 제한 (`js/guard.js`)

### 세션 토큰
로그인하면 **이 기기에서만 만들 수 있는 서명**이 붙은 토큰이 발급됩니다.

- 예전에는 `localStorage` 에 `{"role":"admin"}` 한 줄만 써넣으면 선생님 화면이
  그대로 열렸습니다. 이제는 서명이 맞지 않으면 즉시 폐기됩니다.
- 유효기간: 학생 8시간 · 선생님 2시간 · 전체 관리자 1시간.
  교실 공용 기기에서 앞 사람 세션이 계속 살아 있던 문제를 막습니다.
- **중요한 동작을 할 때마다 토큰이 새로 발급**됩니다(회전). 어딘가 복사해둔
  옛 토큰은 못 씁니다.
- 선생님 세션은 복원할 때 그 반에 관리자 코드가 실제로 등록돼 있는지 서버에
  한 번 더 확인합니다.

### 요청 토큰 — "정해진 시간에 4번"
행동마다 **통이 따로** 있고, 각 통에는 토큰이 4개씩 들어 있습니다.
한 통이 비어도 다른 행동은 그대로 됩니다.

| 통 | 창 | 통 | 창 |
|---|---|---|---|
| 로그인 시도 | 1분 | 마니또 배정 | 5분 |
| 투표 | 1분 | 명단 추가 | 30초 |
| 투표 항목 추가 | 10분 | 학생 관리(삭제·비밀번호 초기화) | 30초 |
| 소원 등록 | 1분 | 소원 수정·다시쓰기 요청 | 30초 |
| 버그 제보 | 5분 | 신고 처리 | 30초 |
| 광고 문의 | 10분 | | |

막히면 **언제 다시 되는지** 알려줍니다. 서버가 요청을 거부한 경우에는 쓴
토큰을 되돌려 줍니다.

### 로그인 잠금
비밀번호를 틀릴수록 잠금이 길어집니다(3번째부터 10초 → 30초 → 1분 → 3분 →
10분). 맞히면 즉시 풀립니다.

### 이 층이 못 하는 것 (솔직하게)
Firebase Authentication도 서버(Cloud Functions)도 없는 정적 사이트라서,
**여기의 어떤 검사도 "서버가 강제하는 인증"이 아닙니다.** 개발자도구로
`js/guard.js` 의 함수를 직접 부르거나 `localStorage` 를 지우면 우회할 수
있습니다. 이 층이 실제로 막는 것은 세션 위조·오래된 세션·연타/도배·
비밀번호 밀어넣기이고, 진짜 강제가 필요하면 Cloud Functions 가 필요합니다.

## Firestore 데이터 구조

모든 반 데이터는 `classes/{학급코드}` 아래로 완전히 격리됩니다. (`학급코드`는
`0601`~`0609` 또는 `1889`)

| 경로 | 필드 | 설명 |
|------|------|------|
| `classes/{code}` | `adminSalt`, `adminHash` | 그 반의 관리자 코드 해시 |
| `classes/{code}/students/{id}` | `name` | 학생 이름 (선생님이 삭제 가능) |
| `classes/{code}/secrets/{id}` | `salt`,`pwHash`,`hasPassword`,`wish`,`wishSetAt`,`wishRewriteNote`,`caringForId`,`caringForName` | 비밀번호 해시 + **본인의 소원** + 다시쓰기 요청 메모 + **내가 도와주는 대상**(guardian → protege 방향) |
| `classes/{code}/secrets/_teacher_` | 위와 동일 | 학생 수가 홀수일 때 자동 참여하는 선생님의 시크릿(가짜 학생 취급) |
| `classes/{code}/meta/state` | `assignedAt`,`studentCount`,`teacherIncluded` | 배정 완료 여부 + 이번 배정에 선생님이 포함됐는지 |
| `classes/{code}/reports/{autoId}` | `name`,`roleTag`,`text`,`reason`,`status`,`createdAt` | 검열에 걸린 투표 항목 시도 → 그 반 담임선생님의 "신고함" 탭. 선생님은 `status`만 `approved`/`rejected`로 바꿀 수 있고 내용은 고칠 수 없음 |
| `adminAccounts/{code}_{studentId}` | `classCode`,`studentId`,`name`,`active`,`grantedAt` | 계정에 붙은 관리자 권한. 부여 시각은 서버 시각으로 못박고, 한 번 만들어진 기록은 수정 불가(거둘 땐 삭제) |
| `voteItems/{autoId}` | `label`,`count`,`weekKey`,`addedBy`,`addedByRole`,`createdAt` | 주간 투표 항목 (반과 무관한 전역 컬렉션). 투표는 규칙상 **정확히 +1씩만**, 라벨·주차·올린이는 수정 불가 |
| `voteWinners/{weekKey}` | `label`,`count`,`itemId`,`decidedAt` | 그 주의 채택 결과. 문서 ID가 **그 주 월요일 날짜**라 한 주에 하나뿐이고, 한 번 정해지면 수정·삭제 불가 |
| `feedback/{autoId}` | `name`,`roleTag`,`message`,`createdAt` | 버그 제보 게시판 글 (반과 무관한 전역 컬렉션, 누구나 읽고 씀. `name`이 비면 규칙 단에서 거부되어 익명 글은 만들 수 없음. 삭제는 전체 관리자만 노출되는 버튼으로) |
| `eggStats/{eggId}` | `count` | 이스터에그별 **발견자 수만** 세는 카운터 (누가 찾았는지는 저장하지 않음) |

- `caringForId`는 "이 학생이 누구를 도와주는 마니또인지"만 담습니다. 반대
  방향(누가 나를 도와주는지)은 어디에도 저장하지 않으므로 학생이 본인의
  마니또를 알아낼 방법이 없습니다.
- 전체 공개/전체 관리자 열람은 모든 학생(+ 참여 중이면 선생님)의
  `caringForId`를 모아 그래프를 재구성하는 방식으로 동작합니다.
- 전체 관리자는 이 그래프의 `caringForId`를 학생 대신 직접 지정할 수 있어
  다음 배정을 몰래 정할 수 있습니다.

> ⚠️ 문서 ID로 `_teacher_`, `_superadmin_`처럼 밑줄 1개짜리는 괜찮지만,
> `__teacher__`처럼 밑줄 2개로 시작·끝나는 ID는 **Firestore가 내부 예약어로
> 취급해 거부**합니다. 참여자/합성 계정 ID를 추가할 때 이 규칙을 꼭 지키세요.

## 🔐 보안 규칙 적용 (직접 하셔야 합니다)

1. [Firebase 콘솔](https://console.firebase.google.com/project/manito-e14c1/firestore/rules) 접속
2. **Firestore Database → 규칙(Rules)** 탭 이동
3. 편집창을 모두 지우고 이 저장소의 [`firestore.rules`](./firestore.rules) 내용을 그대로 붙여넣기
4. **게시(Publish)** 클릭

### 규칙이 막아주는 것
- 학급코드가 `0601`~`0609`/`1889` 형식이 아니면 어떤 경로도 접근 불가
- `secrets` 컬렉션 **열거(list) 차단** → 무작위 수집 방지
- 문서 필드 형태(허용된 키·길이) 검증
- `modeVotes`는 `pororo`/`hachuping` 문서만, `count`(음이 아닌 정수) 필드만 허용
- `feedback`은 `name`,`roleTag`,`message`,`createdAt` 필드만 허용하고 각각 길이 제한(최대 40/60/500자) 적용, 작성 후 수정 불가
- `eggStats`·`modeVotes`는 **정확히 +1씩만** 증가 가능 — 숫자를 크게 써넣어
  발견자 수나 득표수를 부풀릴 수 없음
- `createdAt`은 **서버 시각만** 허용 — 클라이언트가 시간을 위조할 수 없음
- 모든 문자열에서 **제어문자 차단**, 문서 필드 개수 상한
- `adInquiries`는 개별 문서 직접 조회 차단(작성·목록만)

### 앱 쪽에서 추가로 막는 것
- **CSP 헤더**: 허용한 출처(자신 / gstatic / firestore) 밖의 스크립트 로드와
  네트워크 접속을 브라우저가 차단. `object-src 'none'`, `base-uri 'none'`으로
  플러그인 삽입과 base 태그 하이재킹도 차단
- **입력 정화**: 저장 전에 제어문자와 **방향 재정의·제로폭 문자**(글자를
  거꾸로 보이게 해 내용을 위장하는 데 쓰임)를 제거
- **출력 이스케이프**: 화면에 찍는 모든 사용자 입력은 HTML 이스케이프 처리
- `referrer` 전송 차단

### ⚠️ 이 스택의 보안 한계
Firebase Authentication을 쓰지 않는 정적 사이트라서 규칙이 "누가
요청했는지"를 알 수 없고, "본인만 자기 계정 수정", "선생님만 배정/삭제" 같은
사용자별 권한은 앱 로직(비밀번호/관리자코드 확인)에 의존합니다. 개발자
도구를 다룰 줄 아는 사용자가 이론적으로 우회할 수 있는 여지가 있습니다.
교실용 신뢰 수준에서는 충분하지만, 더 강한 보장이 필요하면 Firebase
Authentication + Cloud Functions로 확장하세요.

> `config.js`의 Firebase `apiKey`는 공개되어도 되는 값입니다. 관리자
> 코드와 학생 비밀번호는 추측하기 어려운 값으로 정하세요.
